- `swift-tester` no longer carries the neutral half of test discipline: the AAA form, the `methodName_condition_expectedResult` convention, test size, the "never mock" list and the generic quality gate now come from `spine-toolkit:test-authoring`, read once before the first test of a task. What stays is Apple's — the boundaries a project actually has (`URLProtocol`, in-memory Core Data, the temporary directory, an injected `Clock`, DI through `init`), the state that survives a test (the `UserDefaults` suite, subscriptions, overridden registrations), and three gate lines core cannot carry
- a new paragraph on test doubles in Swift: the language generates none at run time, so the default is a hand-written fake behind a protocol, and where the project already generates them — Sourcery `AutoMockable`, Mockolo, SwiftyMocky, Cuckoo — or declares them with a macro (Mockable, swift-spyable), follow what is there and add no second mechanism
- `swift-reviewer`'s `### Testing Adequacy` keeps its heading and judges by `spine-toolkit:test-authoring` → `## Review`: an assertion that cannot fail, a double standing in for the behaviour under test, state crossing between tests, behaviour no test names, a test asserting more than one behaviour. Unlike the plan-quality findings of the neighbouring skills, a finding there may block
- the core floor moves to `>=2.6.0 <3`: those sections exist only from 2.6.0. `scripts/lint-core-refs.sh` cannot catch a floor that is too low here — it resolves skill names, and the skill itself is older — so a new guard reads `test-authoring` out of the core checkout at the declared floor and requires the four headings
- `tests/foundation/lib/test-discipline.test.bats` also holds the line the other way: no agent restates the neutral prose, and the tester keeps naming its Apple boundaries
