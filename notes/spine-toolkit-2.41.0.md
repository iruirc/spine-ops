- a task folder with no project config above it is a stop, not the defaults: `scripts/resolve-settings.sh` exits 2 with `no project config (SPINE.md) at or above <dir>` for a folder holding `Task.md` (`json`, `show`, `open`, `raw`). Before, a task opened by the physical path of a task repository behind a `Tasks` link ran in another language on other models, silently. A folder that is not a task keeps the defaults and `project_config: null`
- `scripts/task-dir.sh` is the orchestrator's Resolution step 1: it finds a task by id, full folder name or path in the nearest `Tasks` at or above the session's folder, and prints it spelled through `Tasks` — the physical path behind a linked `Tasks` included. Exit 3 not found, 4 ambiguous (every match printed), 5 outside `Tasks`, 2 no `Tasks` or a dangling one; each maps to a locale key (`error_task_not_found`, `error_task_ambiguous`, `error_task_outside_tasks`). An epic's step is dispatched by the `task_dir` the epic hands over, since every epic has its own `2.step`
- `lint-validation-scope.sh` and `lint-report-links.sh` pass the task folder on as given: they resolved it themselves first, so behind a linked `Tasks` every Validation and Review of a task stopped on `no project config` and the regression set was checked by hand
- `task-ranges.sh record` writes a `[BASE_DIRTY]` fingerprint of each repository's uncommitted state into `Base.md`, and `dirty` names a repository only when that state changed since: an environment a project keeps uncommitted (dependencies switched to local checkouts) is no longer a missing row in `lint-validation-scope.sh`. A `Base.md` without the line counts every uncommitted change, as before
- `stage-leftovers`: a watch ends with its session (exit 6 once the session is gone) and `diff` never calls a watch a leftover; the orchestrator stops its own watch with `TaskStop`, never by a pattern that matched every session's watches
- manual checks: a scene takes its data — a file, a clip, an audio track, an account — the way the build gives it to a tester (a generator, a preset, data that ships with the build), never a path on the developer's machine or a camera when the build has a way; a project names its generators in `CLAUDE.md`. A session whose cases start from two scenes or more names its stops: `Stops: before <step>/MC-<n> (~<time>), …`, so a tester can end a sitting at a stop and rebuild no scene the next case does not need
- platforms: no vendored file moved
