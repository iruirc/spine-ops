- **breaking:** a workspace's meta repo is now the workspace folder itself. App repos sit at `<root>/<apps.<key>.dir>/<repo>` (`dir` defaults to `.`) and packages at `<root>/<group-dir or packages>/<pkg>`, each its own git repo ignored by the meta repo; Claude Code and Codex launched in the root see every repo without `--add-dir`. The old layout — `<name>-meta/` beside the repos — is refused by `workspace-docs-regen` and `workspace-add` (exit 4) with the path to `docs/migrations/workspace-nested-layout.md`, which moves an existing workspace step by step and rolls it back
- one config: `workspace-init` writes the only `SPINE.md` into the root through `swift-init --config-dir=<root>`; the first app's stack is `## Stack` (no more placeholder line), every other app and package gets a `## Modules` row, `## Paths` counts from the root, and `## Workspace meta` carries a generated map of the repos. App repos get no `SPINE.md`, `CLAUDE.md`, `AGENTS.md`, `DocsMap.md` or Tasks/Docs links
- `bootstrap.sh` in the root clones every app and package `workspace.yml` names into its folder and skips what is there, so `git clone <meta> && ./bootstrap.sh` sets up a workspace; it needs only git and is regenerated with the meta `.gitignore` block that ignores the repos, symlinked packages included
- `workspace.yml`: `project.apps.<key>.dir` and `project.apps.<key>.git`; `tasks.path`, `docs.path` and `symlink_target` count from the root; a package with no remote is valid; app repo names may hold `_` and `.`
- `.xcworkspace` refs the single `*.xcodeproj` found in the app folder, falling back to `<repo>.xcodeproj`
- `workspace-add` warns when a package folder differs from the last part of its url, since Xcode replaces a remote package with a local folder only when the names match
- `workspace-docs-regen` runs from the root or any folder inside it; marker writes are atomic and keep the file's mode; `workspace-init --resume` finishes a run interrupted in any app's step
