- `ManualChecks.md` is written only for a check that needs a person: the `manual-checks` skill opens with a new section `## Does this check need a person?` — a device action, a visual judgment or an external service; a check that needs none of them is not a case but one of three outcomes: `automate` (work for a phase, a script or a test named in its `**Verification:**` line), `covered` (evidence already exists, cited in `## Scope`), `drop` (a line with its reason in the plan's `## Not automated`)
- a mixed check — one or two actions of a person inside a check made of commands — becomes a script that stops at a prompt and prints PASS or FAIL; its launch is a `**dev-only:**` step in `## Preparation`, and the case holds only the person's steps
- Plan: each `## Manual acceptance` line ends with `needs: device action | visual judgment | external service`; a check a machine could make is not listed there; new optional section `## Not automated` in `Plan.md` (`task-documents`)
- Validation re-applies the criterion to every plan line and every deferred check; the validator writes no code, so a line that needs no person and was not checked becomes a `## Not covered` line, automatable but not automated
- no case, no file: under `[MANUAL_CHECKS] = auto` a run that leaves no case writes no `ManualChecks.md`; `Validation.md` carries `manual checks: none — <why>`, and the Manual test pass item of `OpsChecklist.md` is N/A with that reason instead of Pending; `always` still writes the file
- new lint class `scriptable` in `scripts/lint-manual-checks.sh`: a case whose every step is a command (a backticked command, or "run the command…" and its Russian forms) is named `ManualChecks.md: scriptable: no step needs a person, run it as a script (### MC-<n>.)`; a case with one step a person takes is not named
- Review: a case that needs no person and a `## Manual acceptance` line with no `needs:` are findings, neither blocking
- all five profiles with a Validation stage (FEATURE, BUG, REFACTOR, TEST, QUICK) carry the change in both Method A (the profile scripts) and Method B (the workflow skills)
- none of the six vendored files moved since 2.31.0 (`scripts/lint-manifest.sh`, `scripts/lint-i18n.sh`, `scripts/lint-locales.sh`, `scripts/lint-core-refs.sh`, `scripts/test-foundation.sh`, `conventions/i18n.md`), so no platform has to re-vendor
- source: a field task — a 303-line `ManualChecks.md` with two cases, one of them thirteen shell commands; with this release the first gets one case with the airplane-mode steps, the second gets no case
