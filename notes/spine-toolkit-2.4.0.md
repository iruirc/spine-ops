- new key `done` in `[MODELS]` and `[EFFORT]`, `session` by default. Writing `Done.md` takes `models.done`, else the model of the role that writes it — no longer the `light` model — and `effort.done`, else that role's effort, where it used to run at a fixed `low` no setting could reach. `[MODELS] = [done: sonnet]` sets Done apart from the role's other stages. Under Method B Done is still written in the main context
- a Done that meets a report left by an earlier Done — a redo, a restart, a continue after a hand-back — now treats it as claims to check against the current artifacts and the git log of every repository the task touched, names the archived copy when the orchestrator archived one, and says in its summary how many claims it corrected. Before, a redo could confirm a stale report
- the calibration log keeps one row per task: a Done run again corrects its task's row instead of appending a second, and folds an older release's duplicates into it. `task_id` names a task by its number and a step by its epic's number and its own, since step folders are numbered afresh in every epic
- `task-new` lists `done` among the keys a task's `[MODELS]` may override
- cost: Done now runs on its role's model and effort unless `done:` says otherwise — at most a few percent of a run, against the second reconciling dispatch a stale report used to need
- nothing the platforms vendor moved, so none of them has to re-vendor
