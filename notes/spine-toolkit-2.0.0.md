- **breaking:** `CLAUDE-spine-toolkit.md` now writes every setting as a `[FIELD] = [value]` line, in two blocks — `## Project settings` and `## Task defaults` — with the same names a `Task.md` uses. A config in the 1.x block format stops the run with an error naming the file; `/setup` migrates it without asking a question, backs the old file up and reports what moved
- the ten blocks that carried settings are gone: Language, Mode, Progress, Scale, Reporting, Validation, Docs, Budgets, Models, Effort. Every other block — Persona, Rules, Platform, Agents, Stack, Modules, EstimationDeltas, DeliveryMode, AILeverage, Paths, Orchestration — is unchanged
- the project language is now `[LANG]`, not the `## Language` section
- until `/setup` has run, a `ru` project reads that refusal in English: the resolver stops at the old heading, before anything can read `[LANG]`
- `docs/configuration.md` documents every field: what it governs, its values, its default, and whether a task can override it
- no resolved value changes: a migrated project behaves exactly as it did, with one exception — a value 1.x read past. A config written between 2026-08-28 and 2026-08-31 spells `drive_app` under its pre-rename name `mobile_mcp:`, which the 1.x resolver ignored entirely, falling to the `auto` default; the migration carries that value to `[DRIVE_APP]`, so a project that wrote `off` there stops driving the app. It now lands on what you wrote rather than on the default 1.x fell to — a repair, but a change
- two files the platforms vendor moved in this release: `conventions/i18n.md` and `scripts/lint-manifest.sh`. Both shipped platforms re-vendored them on their own release alongside this one, so nothing to do unless you maintain your own fork of either
- **known issue:** the platform-authoring examples still show the core floor `>=1.3.0 <2` — `tests/fixtures/fixture-platform/.claude-plugin/plugin.json`, `docs/building-a-platform.md`, `conventions/platform-contract.md` and `README.md`. They could not be raised before a `2.0.0` tag existed and are corrected immediately after this release. Write `>=2.0.0 <3`: a plugin copying what they show today declares a dependency that keeps it from loading
