- `scripts/resolve-settings.sh json` returns search roots that exist when a task is reached through a symlinked `Tasks` folder, a chain of them, or a meta checkout; before, every `## Paths` folder outside the task repository came back as a path that does not exist, with exit 0 and plausible JSON, so the stages of such a task were told to search folders that are not there
- the cause was a lexical normalization: the filesystem follows `Tasks` before reading the `..` after it, while `normpath` deleted `Tasks/..`; a found folder now keeps its lexical form only where that names the same folder, and its physical path otherwise, so a project with no links prints exactly the roots it printed before
- nesting and duplicates among roots are judged on the physical folder, so a folder reached through the link is not listed twice
- a `SPINE.md` that is itself a link keeps the directory it sits in as the base of its relative paths
- config lookup is unchanged and now documented in `conventions/task-settings.md` → Project config: the walk upward follows the path as given, so a shared task repository with no `SPINE.md` of its own takes the config of whichever checkout the task was opened through; give it its own config and the settings stop depending on the way in
- `scripts/docs-route.sh` was checked through the same links and already found package registries correctly; it is unchanged
- new `tests/foundation/lib/task-path-symlinks.test.bats`, built in a temporary folder: direct path, one and two links, a meta checkout, a competing checkout config, a task repository without config, `.step` epic inheritance, a linked `SPINE.md`, a linked root, a path with a space, a missing target, a link loop and a dangling link
- no platform change: none of the six vendored files moved since 2.33.1 (`scripts/lint-manifest.sh`, `scripts/lint-i18n.sh`, `scripts/lint-locales.sh`, `scripts/lint-core-refs.sh`, `scripts/test-foundation.sh`, `conventions/i18n.md`), so no platform has to re-vendor
