- a new core skill `artifact-reader` holds the reader and the style rules for the documents a task leaves behind: `Walkthrough.md`, `ManualChecks.md`, `Done.md`, `Plan.md`, `Review.md`, `Questions.md`, `Research.md`, `OpsChecklist.md`, `Validation.md` and `Docs.md`. A platform agent names it as `spine-toolkit:artifact-reader`, so a platform that does needs a toolkit floor of `>=2.30.0`
- the Russian example in `conventions/i18n.md` is fixed; it is the only one of the six vendored files that moves, so the platforms' adapted copies of `conventions/i18n.md` must be refreshed (their `forks.test.bats` pins its sha256)
- `walkthrough: session` now follows the writer's role instead of `light: sonnet`, so `Walkthrough.md` costs more unless `[MODELS]` pins `walkthrough` (for example `walkthrough: sonnet`); the revision after its check follows the same chain, while the check itself stays on `light`
- no setting was added
- `Walkthrough.md` has a fixed skeleton and commit frame: a "How to read" note, a three-row Before / After / Commits table per change, a glossary with an optional ASCII sketch, a Summary with Why, What was done and Main decisions, and a commit-order table; at depth `deep` each commit carries `**In short:**` and `**How verified:**`
- the writer reads `Task.md` and `Research.md` before the commits and lists the 3 to 8 concepts the reader needs
- the walkthrough check gets a second round when the first read lists more than three unclear places, at most two rounds
- `lint-walkthrough.sh` gains the class `style` (a long sentence, identifiers in `## What changed`, a sentence that starts with an identifier, more than two identifiers in a sentence, a commit without its labels) and a `--style <file>` mode; `--current` does not count `style`, and the orchestrator's Walkthrough integrity pass reports `style` findings but does not send `Walkthrough.md` back to its writer for them (the writer already had them once, from its own lint run); every other class is still sent back once
- `lint-manual-checks.sh` is rewritten around the new case format and accepts a folder; a file in the old format reports `case: old format`
- `ManualChecks.md` is now a QA test case: `### MC-N.` with twelve fields and a five-column step table, written for a tester who has no access to the code; files already in the old format are not migrated, and neutral worked examples ship with the skill
- `setup` says so when `[WALKTHROUGH_CHECK]` is off in the project config
- new shared module `scripts/lib/prose.py`; nothing the platforms vendor moved in this part, so none of them has to re-vendor
