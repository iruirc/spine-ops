- Validation runs the task's regression set instead of the whole workspace: every module the task changed, every module that depends on one of them, transitively, and the application that ships them. A module whose code and dependencies are both unchanged is neither built nor tested. The definition lives in `phase-verification` → "Validation's regression"; every Validation brief, Method A and Method B, points at it, and no brief asks for "a full test run" any more
- Validation learns which modules changed from the task's commits per repository, not from the project root's diff: the orchestrator hands it a new contract field, `validation_ranges = {task, rerun}`, computed at step 5.6. Packages in their own repositories next to the app are no longer invisible to it
- a re-run — a fix-review round, a catch-up, a manual re-run — re-runs only what the commits since the last green Validation reach and carries the rest with the count and HEAD it had there. A green Validation writes `[VALIDATED_COMMIT]` lines in its closing block (`task-ranges.sh tips --kind validated`); a FAILED one writes none, so the next Validation runs the whole set; `restart` and a redo of Validation run the whole set too. On BUG, a re-run whose commits miss the scenario's path carries the replay with the status it had
- `Validation.md` carries a `## Regression set` table (`| Repository | Module | Why | Run | Tests | HEAD | Log |`, `Run` = `ran` or `carried <sha>`), described in `task-documents`; the new `scripts/lint-validation-scope.sh` checks it against the task's commits, and the validator runs it before it returns
- Review runs that lint first and re-runs no suite when it is clean; a module of the set Validation did not run is a Major, blocking finding, and a module run outside the set is a Minor one (`phase-verification` → Review)
- `task-ranges.sh`: the `validated` kind, and two commands the lint uses, `dirty` and `count`
- platforms: none of the vendored files moved. A platform's validator should say how it finds modules and dependents in its build — spine-platform-swift 1.36.0 and spine-platform-kotlin 1.24.0 do
