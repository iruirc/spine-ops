- the `ran:` line a phase writes under a check after a green whole-module run counts tests with a neutral word and quotes the run's result line verbatim: `ran: <repository> <module> HEAD <sha> tests <N> result "<result line>" log phase-evidence/phase-<id>/<module>.log`. Before, it took XCTest's `Executed <N>`, which a Swift Testing log does not hold, so a reviewer found nothing matching it in the log
- which line of a log is a result line, and where its count stands, comes from the platform's `test-frameworks` (topic **testing**) for the stack's `tests` value. A log with several result lines gets one `result` per line and `<N>` is their sum; a result line that counts no tests (`Executed 0 tests` beside a Swift Testing run) is not quoted; a log with no result line gets no `ran:` line
- a `ran:` line written before this form, with `Executed <N>` and no `result`, is carried by Validation the same way, and a log that lacks the words is no finding against it
- the `Tests` column of `## Regression set` is the sum of the counts of the run's result lines
- the phase brief of every profile and the five `workflow-*` skills carry the new form
- `/setup` has one **Permissions** step for Claude Code and Codex CLI. `scripts/spine-permissions.sh` (was `codex-permissions.sh`) takes `--runtime claude-code|codex-cli`; in Claude Code it names the folders Spine writes outside the project that `permissions.additionalDirectories` lacks and, once the user agrees, writes them to `.claude/settings.local.json`
- the Codex write roots add the tasks folder and the documentation `places`, compared by realpath; a `places` glob such as `Docs/**` stands for the folder before it
- the orchestrator checks the permissions once per run in Claude Code as well as Codex CLI; the `SPINE.md` template says which folders get write access in each runtime
- a choice picked in a question that shapes an agent's brief (which review findings to fix, what to do with one) is typed before a `Workflow` run is dispatched: the host passes only the owner's last typed message to the agents. The orchestrator prints one line with every choice and dispatches on the typed reply
- fix rounds are counted by their `R<n>` row id, so no phase id repeats; a fix phase keeps its id and title
- a fix round that left findings unfixed stops its range before Validation and is not closed: its row stays at `⏸`, and the orchestrator asks for a new round on what is left, to accept it, or to stop. In `auto` the rounds-spent question offers the same. A later `continue` on a task with a paused round asks again rather than offering a catch-up
- after an `APPROVED` review the owner may have findings below Major fixed: "fix review 001 m1 m2" or, in `manual`, a new option at the stage prompt
