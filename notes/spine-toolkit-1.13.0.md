- every setting a task runs with is now resolved by one script, `scripts/resolve-settings.sh`, along the chain `Task.md` → the epic's `Task.md` → `CLAUDE-spine-toolkit.md` → the default; `scripts/resolve-tuning.sh` is gone, and `models` and `effort` are two fields among the rest
- three fields travel in the Outbound Contract — `drive_app`, `manual_checks`, `phase_verification` — so a validator no longer reads the config for them, and a step of an epic receives its own values through the step reader. The driver deliberately stays a pre-flight concern
- a run prints what it resolved and from where, before the first dispatch. `## Progress` takes a new key, `settings: diff | full | off`, `diff` by default, and `scripts/resolve-settings.sh show <task dir> [--all]` prints the column at any time
- an epic's `[DOCS] = [off]` now reaches its `.step/` children, and an epic's `[SCALE]` now reaches them in `lint-artifact-budget.sh` too, as it already did in the contract. A step's own field still overrides in either direction
- a value the resolver cannot use is reported and the chain continues to the next source, where the two replaced readers stopped at the bad value. A typo in a task field therefore resolves to the project's choice rather than to the built-in default
- two diagnostics changed wording, having moved into the resolver: `scale 'x' not recognized, treating as full` became `Task.md [SCALE]: 'x' not recognized, skipped`, and `budget 'L' not recognized, keeping the default` became `<config> ## Budgets: 'L' not recognized, skipped`
- `scripts/docs-route.sh` and `scripts/lint-artifact-budget.sh` now exit 2 where they used to fall back to defaults: an unreadable config, or a task directory that does not exist, is an error rather than silence
- the reference driver floor moves to `>=1.13.0 <2` with this release
