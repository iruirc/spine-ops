- the three validators classify a failing test by spine-toolkit's `### Failures outside the task` and read the project's known failures registry from the brief's `known_failures`, never writing it: a known failure outside the task leaves `PASSED`, an unregistered one green on its retry gives `PASSED_WITH_FLAKES` with `continue`, a failure inside the task is `FAILED` whatever the registry says. `FLAKY` stays with a TEST task's own added tests. They write `## Outside the task` and return `outside_failures` and `known_failures_cleared`
- a Gradle or Maven test task that exits non-zero over failures that are all outside the task is classified, not `FAILED`; a compile or build error stays `FAILED`. The regression set's run and every Gradle test form carry `--continue`, a Maven test step `-fae`, so one module's failure does not stop the others; a retry uses `--rerun --tests`
- a re-run, and a first Validation, carry a module from a phase's `ran:` line or a green row of an earlier Validation; a null `rerun` runs what no carried run covers rather than the whole set. A `reach` line of the lint is left for Review
