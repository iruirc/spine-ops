- **Behavior change:** `ManualChecks.md` gets a second style, `brief`, and it is the default. New field `[MANUAL_CHECKS_STYLE] = brief | full` in the project config, overridable per task; `/setup` asks who walks the manual checks (you or another developer → `brief`, a separate tester → `full`). The file names its style in a `[STYLE] = <value>` line after `[COVERS]`; a file without the line reads as `full`
- a `brief` file holds `## Scope`, `## Preparation` (scenes `S1`…`Sn` only), `## Cases`, `## Not covered`, `## Code references` and a closing `**Result:**` line; a case is four fields — `**What it checks:**`, `**Start:**`, numbered steps with the expectation after `→`, `**Failure looks like:**` — and no status of its own; no Run record, bug-report template, Troubleshooting, Charter, screen map or word table
- code references leave the case: the `**Code:**` field is gone in both styles, and every case has one row in a `## Code references` table at the end of the file. The lint names `**Code:**` inside a case once as the old format
- no instrument in the file a person walks: `**By instrument:**`, `## Reading the verdict` and any request to record the screen are gone; a measurement the agent can take goes to `Validation.md`, one it cannot to `## Not covered`. The lint's new `instrument` check names what is left, in any case field and in `## Preparation`
- a new section `## What a case must prove`: a case tells the build before the change from the build after (checks that pass the same on both fold into one "nothing broke" case, or go when automation covers the regression); it rests on behaviour the diff touches; the eye decides; no line is for a developer; one check is one case, with conditions (language, theme, text size, device, orientation) as a table in `**Test data:**`
- `## Does this check need a person?` now asks first whether the diff changes the behaviour; a check it does not change is neither a case nor a Pending, including one deferred only because a driver could not reach it
- no line budget for `ManualChecks.md` in either style: the lint's `budget` check is gone, and `conventions/task-scale.md` names no ceiling for it
- the fresh reader's check gains a ninth smell, `redundant` (a repeat, a caveat said twice, text not for this reader, a case repeating another under other conditions); the revision deletes such a place instead of rewriting it, and the note reports the file's length before and after: `ManualChecks.md check: N place(s), revised, A → B lines.`, plus `The revision lengthened the file.` when it grew. In `brief` the reader knows the app but not the task
- a Validation that refreshes a file in the other style rewrites it whole in the run's style, keeping case ids; the first `brief` run after the update meets every existing file this way
- Review judges each case by `## What a case must prove` too, and checks an `OpsChecklist.md` N/A reason that cites the diff against the diff
- `ops-checklist`: when the checklist is written for a task, an item is judged against the task's diff, not the product; behaviour the diff does not touch (directly or through code on its path; when in doubt, it touches) is N/A with the reason `not changed by this task: the diff touches <X>`
- no platform change is forced by a vendored file: none of the six moved since 2.35.0. The platforms' validators move to these rules in spine-platform-swift 1.34.0 and spine-platform-kotlin 1.22.0, which require this release
