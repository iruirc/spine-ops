- `spine-toolkit:test-authoring` now carries the neutral half of test discipline, not only the choice of framework: the AAA form, the `methodName_condition_expectedResult` name, one behaviour per test, isolation, and the rule that a test exists to fail. Written without naming a framework, a library or a platform skill, so it holds for every ecosystem
- a vocabulary of test doubles — dummy, stub, spy, mock, fake — with the rule for choosing between them (verifying state takes a stub or a fake; verifying calls takes a spy or a mock and ties the test to how the code works), the boundaries a double belongs on, and the three places it never belongs: the code under test, the helpers it calls, value transformations
- a `## Before you deliver` checklist for the agent that writes tests, and a `## Review` section for the agent that judges them: five findings, and unlike the neighbouring `phase-verification` and `security-lens` these may block — a test that cannot fail is a defect in what was delivered, not a misjudged plan
- Review of FEATURE, BUG, REFACTOR and TEST judges test quality by that one section. The TEST profile's own copy of the criteria, the only written-out set core had, is gone: the four briefs now carry one clause with one wording
- `docs/building-a-platform.md` says which half stays with the platform — what counts as a boundary in this ecosystem, what resets state, which library makes the double — so the next platform tester is written without the discipline copied into it
- a platform plugin that has not moved yet keeps working unchanged: its agents carry their own copies until `spine-platform-swift` and `spine-platform-kotlin` release their halves
- nothing the platforms vendor moved, so none of them has to re-vendor
