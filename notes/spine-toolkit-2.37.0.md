- **Behavior change:** an EPIC can walk its steps' manual checks in one collective pass at its end. New field `[MANUAL_CHECKS_PASS] = per-step | end` in the project config, overridable per task, `per-step` by default; a step inherits the epic's value. `/setup` does not ask. Under `per-step` nothing changes
- under `end` a step's validator marks its cases for the pass, by the `manual-checks` skill's new `## Marks for a collective pass`: `**Runner:** agent` on a check deferred only because a driver could not reach it (it stays a case of the step's file, and counts when `auto` decides whether the file is written), `**Device:** real | <model>` when the case needs a real device, `**Order:** first | last — <why>` when it needs untouched state or changes it irreversibly. The brief case template marks the three as written only under `end`
- a new EPIC stage `Acceptance` (Research → Plan → Execute → Acceptance → Done), only under `end`: the validator collects every unmarked case of the steps, walks through the driver what an agent can walk and records it in the epic's `Validation.md` under `## Agent verdicts`, and writes one pass file `<epic>/ManualChecks.md` for the person by the skill's new `## Collective pass`: a `[PASS]` line, sessions by device (`### Session <n>.`), cases copied whole and never merged (`#### <step>/MC-<n>.`), `first` → the rest → `last` within a session, scenes of the steps merged, one interface language, a time estimate per session, one `**Result:**` line. The lint knows the pass file. The stage then stops for the person. It never runs twice: an epic `Validation.md` that says PASSED is kept, a FAILED one is retried
- the epic's Done reads the marks — PASS, `FAIL (<why>)`, `BLOCKED (<why>)` and the new `DROPPED (<why>)` — writes them back into each step's own file, sums them up in a `## Manual acceptance` section of `Done.md`, and turns every FAIL into a BUG step of the epic (`[MANUAL_CHECKS_PASS] = per-step`, the failed case as its reproduction); the epic closes after those steps. A collected case with no mark — a blank, or one missing from the pass — stops Done with the list
- new script `scripts/manual-checks-pass.sh` with `collect`, `marks` and `writeback`: all-or-nothing, idempotent; a step id is its folder name up to the first `-`, the full stem where two steps share a prefix; a step whose own `Task.md` sets `per-step` walks its own cases and is not collected
- the orchestrator routes an `end` epic whose steps are done to `Acceptance` until its `Validation.md` says PASSED; the Validation briefs of every profile carry the `end` note; `conventions/driver-contract.md` says a check is "deferred", not "deferred to a human"
- the platforms' validators move to these rules in spine-platform-swift 1.35.0 and spine-platform-kotlin 1.23.0, which require this release; the core floor of every reference copy is `>=2.37.0`
