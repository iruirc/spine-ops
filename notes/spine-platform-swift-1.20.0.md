- the workspace generator knew two of the `tests` axis's three values, spelled them a third way, and never handed the choice to the apps it generates — so a workspace that answered `xctest` shipped XCTest packages beside a Swift Testing app and nothing went red. `test-frameworks` now opens with `## Spelling`, one row per value giving the token, the axis value and the section, and it is the canonical spelling for every consumer: the `swift-init --tests` flag, `defaults.tests`, and the new `apps.<key>.stack.tests`
- three consumers are pinned to that table by tests, so a fourth axis value cannot land in one place and be missed in the others: the tokens `workspace.yml` accepts, the set of `Tests/` stub variants, and `swift-init`'s flag rows. A value added to `## Axes` and nowhere else fails three tests at once, and the chain then walks forward one guard at a time until the stub exists
- `defaults.tests` accepts `quick-nimble`, and a package generated with it gets a `QuickSpec` stub with Quick and Nimble in its manifest. The framework's packages ride the placeholder substitution that generation actually executes — `{{TEST_FRAMEWORK_MANIFEST_DEPS}}` and `{{TEST_FRAMEWORK_TARGET_DEPS}}`, each alone on its line, replaced by lines or removed entirely when empty — not the `WORKSPACE_PKG_*_DEPS` marker pairs, which nothing fills at generation and which stay `wspkg::adopt_to`'s input for a foreign manifest
- the axis reaches the apps. Both `s06b` invocations pass `--tests`, resolved through `wspkg::tests_kind` so that a `workspace.yml` with no `defaults:` block still yields a value; batch prefers the new optional `project.apps.<ios|macos>.stack.tests` when the app declares it, validated by P-rule 9 against the same tokens
- **every generated `Package.swift` changes shape**, on all three values: `.testTarget` goes from one line to three, with a trailing comma after the package name. SwiftPM behaviour is unchanged, but the text differs from 1.19's, so anything matching the old single-line form breaks. `wspkg::adopt_to` never rewrites a test target, so a package brought in by `workspace-add --incorporate` keeps the old shape while `--new` produces the new one — both forms now coexist in one workspace
- an app generated in batch mode used to be Swift Testing whatever the workspace answered, because no flag was passed; it now follows the workspace. Interactive generation is pre-answered rather than changed: `swift-init`'s question arrives with the workspace's answer as its default, still overridable per app
- `quick-nimble` adds two network dependencies to every package it generates — Quick from 7.6.0 and Nimble from 13.8.0, transitively CwlCatchException, CwlPreconditionTesting, swift-numerics, swift-algorithms and swift-argument-parser. A workspace on `xctest` or `swift-testing` has none. The floors live in `workspace-package.zsh` and are not configurable from `workspace.yml`
- the `defaults.tests` validation message now lists three tokens, and membership is compared literally: it was matching the value as a glob, so `tests: "*"` and `tests: "swift-*"` validated as real tokens
- existing `workspace.yml` files stay valid and packages already on disk are untouched: the third token widens an enum, `apps.<key>.stack.tests` is optional, and no unknown-key whitelist guards the app stack
