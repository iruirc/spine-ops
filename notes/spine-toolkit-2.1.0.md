- `Walkthrough.md` opens with `## What changed`: one item per observable change, before and after on one concrete case, each naming the commits that build it. A commit section says which change it serves, and commits that carry no decision — plan ticks, phase closings, documentation that mirrors code — close the log as one `### Bookkeeping` list
- the header holds the perimeter as a table and a pointer to the verdicts, and nothing about the run's history. At `deep`, `## Summary`, `## Commit order` and a commit's sub-headings lose their line counts: what bounds them is their scope. An identifier — a test case, a review finding, a step — is cited after the sentence that says what it is, never used as its subject
- new field `[WALKTHROUGH_CHECK] = [auto|on|off]`, `auto` by default: at `deep` a fresh agent of the writer's role reads the finished file and nothing else, retells what changed and names every place it had to guess; the writer revises once from that. `off` turns it off, `on` checks a `brief` file too. It costs one light dispatch per write that changed the file, and one writer dispatch more when it finds something
- new key `walkthrough` in `[MODELS]` and `[EFFORT]`, `session` by default: writing and revising `Walkthrough.md` take it first, then `light`, then the writer's role. `[MODELS] = [walkthrough: opus]` raises that one file without moving any other light call
- an epic now hands a step it runs itself that step's own `[WALKTHROUGH]` and `[WALKTHROUGH_CHECK]`, read from the step's folder. Before, such a step wrote at `deep` whatever its own field or a `lite` scale said. A step created by the Plan stage of the same run still takes the epic's values, as it already did for `[DRIVE_APP]`, `[MANUAL_CHECKS]` and `[PHASE_VERIFICATION]`
- `warn_tuning_unrecognised` lists the new key among the valid ones, and `[EFFORT]` entries are documented as `<key>: <value>`
- the 2.0.0 known issue is fixed: the platform-authoring examples show the core floor `>=2.0.0 <3`. `conventions/task-scale.md` names `[NEED_REVIEW]` as the exception to the floor
- the reference driver floor moves with this release; nothing the platforms vendor moved, so none of them has to re-vendor
