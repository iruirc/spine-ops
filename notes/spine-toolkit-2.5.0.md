- new skill `spine-toolkit:test-authoring`: which test framework a file is written in, decided in one place for every agent that writes test code — the tester, the developer adding a regression test, the diagnostics agent sketching one, the init skill writing a project's first test. In order: the framework of the file being extended, then a surface only one framework can drive, then the value the project gives the test-framework axis for that module (`## Modules`, else `## Stack`), then the tests nearest the code. It never mixes two frameworks in one file and never brings a second one into a target on its own
- the platform contract fixes what the `tests` axis means wherever a platform declares it — its values name the frameworks tests are written in — and adds an eleventh topic, **testing**, through which a platform answers with its own syntax: one section per value of its axis, plus the surfaces that force a framework whatever the axis says. Core still names no framework, and `method-skills.test.bats` now holds that line for the new skill too
- a platform without a `testing` row keeps working exactly as before: the row is an ordinary declared absence, and nothing in this release changes how an agent is dispatched. `spine-platform-swift` and `spine-platform-kotlin` pick the topic up in their own releases
- `docs/building-a-platform.md` teaches the row and names the five agents it binds; the reference fixture platform answers it
- nothing the platforms vendor moved, so none of them has to re-vendor
