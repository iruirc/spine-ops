- a reconfiguring `/setup` (state C, Overwrite or Backup-and-overwrite) no longer drops the project's own blocks of `SPINE.md`: `## Agents`, `## EstimationDeltas`, `## DeliveryMode`, `## AILeverage`, `## Paths` and any heading outside the template are carried verbatim and in place. Before, a reconfigure silently lost `## Paths`' `Known failures` line, and the registry fell back to `Tasks/KnownFailures.md`
- of a carried project block only the project's lines are kept; the template's note in parentheses comes from the new template, so a newer note reaches a configured project. A block holding only the template's own lines is not carried and not reported
- `## Persona` and `## Rules` are compared with the template; when the project edited them, one question `auq_reconfigure_template_blocks` asks Keep yours (the default) / Take the template's. The `Communication language:` line is outside the comparison and always follows the language chosen in the run, so a project that ran `/lang` is not asked for nothing
- `## Platform`, `## Orchestration`, the two field blocks, and the platform's `## Stack` and `## Modules` are written anew as before; a row typed into `## Modules` by hand still does not survive a reconfigure, and `docs/configuration.md` now says so
- the state C report adds `report_reconfigure_kept_blocks` with the blocks it carried
- the `SPINE.md` header no longer says "Do not edit by hand"; it names the blocks `/setup` writes and the ones the project fills, which survive `/setup`
- new `## Paths` line `- Scene data: <path>`: the project's document of the generators and presets that give a manual-check scene its data, written from the project root or `~` as `Known failures` is. `resolve-settings.sh json` prints it as `scene_data`, `""` with no line
- `manual-checks` takes a scene's generators from the file `scene_data` names, and falls back to the project's `CLAUDE.md`; with neither, getting the data is a `**dev-only:**` step as before
- no vendored file changed
