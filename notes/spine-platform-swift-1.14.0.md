- `workspace-docs-regen` is now a script the skill runs, `scripts/workspace-docs-regen.zsh`: every marked section of the meta-repo and package docs has one tested format, `--check` reports real drift, and the command runs from any repository of the workspace
- it also writes the `.xcworkspace` and the `folders` of the `.code-workspace`, keeping the editor settings; `workspace-init` and `workspace-add` run it, so a new package reaches Xcode and VS Code, and the meta-repo README lists the packages right after init
- the toolkit's text sits under markers: the archetype paragraph of a package's `## Boundary contract` (lines below it stay the package's own), the archetype rules in `CONTRIBUTING.md`, and the Quickstart, Daily ops and Schema sections of the meta-repo README; `## Project-specific rules` is no longer under a marker regen would overwrite
- the Quickstart clone commands follow `package_groups`, and a package's `CLAUDE.md` points at the meta-repo two levels up
- a workspace created before 1.14.0: run `/workspace-docs-regen --adopt`, review the diff and confirm. It puts those sections under markers and replaces the text earlier releases left there — the promise of a `workspace-check` command, the "Cluster 2" commands — and keeps what you wrote
- `workspace-docs-regen --repair` and `--adopt` preview what they would change and write nothing until you rerun them with `--yes`; a preview that meets a file it cannot repair says so and exits 2
