- `scripts/task-dir.sh`: a path to `Tasks`, a status folder or an `_archive` is exit 2, `not a task folder`, instead of a task folder that then ran on defaults; a child of `Tasks` with a `Task.md` is a root task, and its subfolders are no longer found by id as if it were a status folder; a status folder that cannot be read is passed over instead of a traceback with exit 1, a code the orchestrator has no key for
- `stage-leftovers`: an app that started during a stage and left a double-forked helper under PID 1 is no longer offered for killing as the stage's orphan. `diff` compares a candidate's origin with the session's — on macOS the responsible process, elsewhere the session markers in its environment — and leaves out one that differs; when either cannot be read the orphan is shown as before. `origin <pid>…` prints what `diff` compares
- development of the toolkit itself: `scripts/test-foundation.sh verified` runs the `changed` selection for what differs from the newest tree in the history of `HEAD` that `.git/spine-verified-trees` holds, and when green on an unchanged tree records `<tree> via <that tree>`. A fix after a green `all` is checked with it, and a release takes such a tree as verified, so a release right after a plan with review fixes no longer runs the full suite. With no verified tree in the history it says so and exits 2
- `changed` and `verified` search `tests/foundation/integration` too once it exists: a test there that names a file is selected, and a change that selects the whole suite selects both directories
- a test asserts with `[[ ]] || false`: bash 3.2 does not fail a bats test on a bare `[[ ]]` that is not its last command, and `bats-assertions.test.bats` holds every test file to it
- platforms: `scripts/test-foundation.sh` moved; spine-platform-kotlin 1.26.0 and spine-platform-swift 1.38.0 carry its new hash
