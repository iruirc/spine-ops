- `kotlin-ui-validator`, `kotlin-server-validator` and `kotlin-jvm-validator` keep every log `Validation.md` names with spine-toolkit's `evidence.sh keep` into `<task_path>/validation-evidence/<timestamp>/`: the raw log goes to a `raw/` git never sees, and `Validation.md` cites and quotes only the scrubbed excerpt beside it. Their `--match` regexes keep `JUnit XML: N tests`, Maven's `Tests run:`, failed Gradle tasks and `Execution failed for task`, Kotlin compiler `e: ` lines, `error:`, `BUILD FAILED` and Maven `[ERROR]`. The validators' own redaction regex is gone: the excerpt is scrubbed by core's rules
- device and process logs are kept the same way: logcat is written on the device under the run's timestamp, pulled into a temporary folder, removed from the device and kept as `logcat`; a desktop app and a server start through `long-run.sh start --parallel` and their logs are kept as `app-process` and `boot`; `kotlin-server-validator` keeps the response bodies and CLI streams it quotes under slug names, and shows secret request headers and query parameters as `***`
- `kotlin-ui-validator` saves a screenshot into the folder `evidence.sh raw` prints; it enters history only through `evidence.sh keep-image`, after the validator looked at it and saw no credentials, tokens, keys or personal data
- an `evidence.sh` exit 2 naming `## Redact`, the project config or the task folder fails the step with that message; it is not an older core
- works with spine-toolkit 2.51.0 and later, the release that ships `evidence.sh`
