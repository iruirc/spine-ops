- **Behavior change:** in Claude Code, `light` and `validator` default to the new tier `fast` instead of `sonnet`, and `fast` with no `[MODEL_TIERS]` line runs on the session's model; a project that names neither key in `[MODELS]` and has no `[MODEL_TIERS]` now runs both on the session's model instead of Sonnet — so does a 1.11.0 `validator: platform`; projects made from an earlier template are unaffected because they write `sonnet` explicitly, and `/setup` offers the migration that restores Sonnet through `fast@claude-code: sonnet`
- one `[MODELS]` now serves Claude Code and Codex: a key may say `fast`, and the new project-only block `[MODEL_TIERS] = [fast@claude-code: sonnet, fast@codex-cli: <model>]` in `SPINE.md` says what `fast` is in each runtime; no line for the runtime → `session`, so Spine never picks a model on its own; `fast@<runtime>: session` pins the session's model for one runtime
- every `[MODEL_TIERS]` line is checked against its own runtime's file on every run; a tier other than `fast`, an unknown runtime, a model outside that runtime's vocabulary or one it reads as session, or a tier as a value is skipped with the usual `not recognized, skipped`; a `[MODEL_TIERS]` in a `Task.md` is not read
- `scripts/resolve-settings.sh json` keeps `models` final and adds `model_tiers`, the tier, model and source of every key resolved through `fast`; a new stderr line, `'<entry>' has no fast@<runtime> in [MODEL_TIERS], read as session`, comes only from the source that decided the key
- the settings column and the opening block name the result: `validator: fast → sonnet`, `validator: fast → session, no fast@<runtime>`, and in Codex a Claude name from the project config as `light: sonnet → session`, so the replacement is visible at launch before any `/setup`
- the launch texts for a `Task.md` or `--set` source name the source, the reason, the result and the action, and point at the project config's `[MODEL_TIERS]`; a same-source override no longer reports a replacement that did not happen
- new `scripts/model-tiers.sh`: `check` names `sonnet` entries and a missing `fast@<runtime>` line (only when a key uses `fast`); `apply --migrate` rewrites `sonnet` entries to `fast` and adds `fast@claude-code: sonnet`; `apply --set fast@<runtime>=<model>` adds a line and never overwrites one; idempotent, keeps comments, line endings and permissions
- `/setup` step 6e, every state but the silent format migration: offers to move `sonnet` entries to `fast`, and in Codex asks the model for `fast` when a key uses it and the line is missing; the answer, "keep the session's model" included, is written, so the question does not come back; this replaces the old one-time note that Claude models run on the session's model in Codex
- an epic dispatches each step on the tier-resolved models of the step's own resolver run, so a step's `fast` and a run's `--set models.<key>=fast` reach the step; the literal tier is never dispatched as a model name
- the template writes `[MODEL_TIERS] = [fast@claude-code: sonnet]` and `light: fast`, `validator: fast`; `docs/configuration.md` gains `[MODEL_TIERS]` and a table of what each `[MODELS]` value becomes in Claude Code and in Codex
- `scripts/codex-permissions.sh check` no longer names an External packages root missing when the `writable_roots` Codex uses cover it or a parent folder (the project's list when set, else the user's); an uncovered root is probed and reported as `unlisted` (writable, nothing changes in this run) or `missing`; the orchestrator reports one line per item
- no platform change: none of the six vendored files moved since 2.33.2 (`scripts/lint-manifest.sh`, `scripts/lint-i18n.sh`, `scripts/lint-locales.sh`, `scripts/lint-core-refs.sh`, `scripts/test-foundation.sh`, `conventions/i18n.md`), so no platform has to re-vendor
