- new field `[SECURITY] = [auto|on|off]`, `auto` by default, in `Task.md` and in `## Task defaults`: whether a FEATURE, BUG or REFACTOR task gets the security lens. At `auto` a `light` triage reads the task first, and the lens runs only when the task touches credentials, the network, stored data, an external entry point, authentication, personal data, permissions or a third-party dependency; `on` runs the lens every time without a triage, `off` runs neither. `scale` does not move it
- the lens now runs on BUG, beside diagnostics and architect in the Diagnose panel, and on REFACTOR, before Analyze, where it names the security properties the move must keep. On a `lite` task it runs before Plan. Before this release a `lite` FEATURE never got it, and BUG and REFACTOR never did at all
- at `auto` every FEATURE, BUG and REFACTOR run now pays one `light` triage dispatch, whatever its scale — including `lite` tasks and BUG and REFACTOR tasks, which dispatched no security agent before. A `full` FEATURE task that touches none of the perimeter no longer pays for the lens itself; `[SECURITY] = [on]` puts it back on every task
- when the lens yields no findings, the analysis records why in one line, and Review raises a non-blocking finding when the diff touches the perimeter after the triage skipped the lens or the lens returned nothing
- new skill `security-lens` holds the perimeter, the triage, the question for each profile, the verdict lines and the review rule; new dispatch label `security:triage`, a `light` call
