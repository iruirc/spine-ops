- `Walkthrough.md` gets a depth: `walkthrough: brief | deep | off` in `## Reporting`, `[WALKTHROUGH] = [brief|deep|off]` in `Task.md`, and the contract field carries the depth into the writing agent's brief. `deep` writes a glossary, the commit order and a section per commit — what appeared, the failure it is written against, how that is closed, which alternative was rejected; `brief` keeps the previous shape, a summary and a bullet per commit
- `deep` is the default and `on` now reads as `deep`: a config left alone writes more than it did, and the run says so once. A project that wants the old shape writes `brief`
- the skill names its reader — an engineer who did not write the code and was not on the task — and its budgets bound what a section covers, not how clearly it says it
- per-phase verification has a definition: a new skill `phase-verification`, and every phase of `Plan.md` opens with `**Verification:** <internal|surface|behaviour|full>`, chosen from what the phase changes for the modules that depend on it. The full regression belongs to Validation
- the implementing stage runs what that line names, once; a missing line is written and a line the diff outgrew is raised, never lowered. Review reports a missing line, an under-claimed rung, or a phase repeating the full regression, and none of them blocks
- `phase_verification: proportional | full` in `## Validation` and `[PHASE_VERIFICATION]` in `Task.md`; there is no `off`. The agents resolve it themselves, so the Outbound Contract does not change
- "targeted tests", "tests for the touched scope" and "the newly added tests" — three undefined names for a phase's checks — are gone from both dispatch forms
- the reference driver floor moves to `>=1.8.0 <2` with this release; nothing the platforms vendor moved, so none of them has to re-vendor
