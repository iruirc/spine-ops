- `Walkthrough.md` is written once, at Done, by default: `[WALKTHROUGH_WHEN] = [done]`. An implementing stage no longer writes it and its checks; the stage's notes say `Walkthrough.md is written at Done ([WALKTHROUGH_WHEN] = done).` `[WALKTHROUGH_WHEN] = [stage]` brings back a refresh after every stage with code. An epic hands the field to each step, falling back to its own value
- `[WALKTHROUGH_CHECK]` takes `once`: one fresh reader and at most one revision. `auto` resolves to `once` at `deep` instead of `on`; `[WALKTHROUGH_CHECK] = [on]` keeps the second round
- a Review finding about a `Walkthrough.md` that is current is closed by one agent, `walkthrough:patch`, which edits the file in place instead of a rewrite and two checks. A patch closes only the findings it was handed; a patch that closes none asks the owner
- `[ARTIFACT_CHECK]` is split into `[PLAN_CHECK]` and `[DONE_CHECK]`, each `on|off`. `[ARTIFACT_CHECK]` stays as the pre-split spelling of both: `resolve-settings.sh` sets both from it and warns once per source when its value is `on` or `off`, naming the two lines to write by hand; `auto` is taken silently. `/setup` on an existing config replaces the template's `[ARTIFACT_CHECK]` line with the two new ones instead of appending them
- `lint-walkthrough.sh --history-only` leaves out the coverage classes (`missing`, `count`, `range`, `behind`): under `[WALKTHROUGH_WHEN] = [done]` a stage boundary before Done reads the file with it, since no writer has brought it up to the newest commit yet
- platforms: no vendored file moved
