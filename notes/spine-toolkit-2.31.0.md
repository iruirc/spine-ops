- new field `artifact_check` (`[ARTIFACT_CHECK]` in `Task.md` and the project config, values `auto`, `on`, `off`): at `scale = full` it is `on` by default and costs one extra agent call after Plan and one after Done, a fresh reader that retells the file and names the places it could not follow; `[ARTIFACT_CHECK] = [off]` in `SPINE.md` or `Task.md` turns it off in one line; `auto` is `off` at `lite`, so a `QUICK` task checks nothing unless it says `on`
- the check revises the file once at most, never a second round, and a failure of the reader never stops the run; a `Done.md` revised by the check after Done's own commit may be left uncommitted, the same as `walkthrough:revise`
- new `[BUDGETS]` entries beyond the line ceilings, set per task (`Task.md`), per epic (its `Task.md`, inherited by its steps) and per run (`--set budgets.<key>=<n>`): the key `words-per-sentence` (30 by default, counted in words, not lines) is the sentence threshold of both `lint-artifact-readability.sh` and the style class of `lint-walkthrough.sh`; each key is inherited on its own, and an entry that is zero, negative or not a number is reported and skipped
- `[BUDGETS]` now stands under `## Task defaults` in the `SPINE.md` template; a config that kept it elsewhere keeps working
- new `scripts/lint-artifact-readability.sh` measures `Done.md`, `Plan.md`, `Review.md`, `Research.md`, `Questions.md` and `OpsChecklist.md` and reports `<Artifact>.md: <class>: <what> (<where>)`: `sentence` (over `words-per-sentence` words), `identifiers` (backticks piled into the first section or one table cell), `label` (a label such as M1 or Q2 with no gloss), `question` (a `Questions.md` entry with no `**Question:**`), `format` (`OpsChecklist.md` written as a table); exit 0, 1 findings, 2 usage; it takes a task folder or one file
- `--words-per-sentence <n>` is accepted by `lint-artifact-readability.sh` and by `lint-walkthrough.sh` and replaces the threshold the folder resolves to, so a run passes its own budget to both
- known limits of the `label` rule, written in the script header: a short code of the same shape (EC2, MP3, Q3, V8) reads as a label when it starts a sentence or stands in a sentence of fewer than four words; a key before a title (`M1. Title`) is not checked
- every writer runs the lint once on its own file and fixes its findings once; what is left is named in the stage summary, and nothing sends a file back for a readability line a second time
- the closing block: the machine lines of an artifact are now its last lines, after the body and a blank line: the marker lines (`[DONE_COMMIT]`, `[REVIEWED_COMMIT]`, `[REVIEW_FIXES]`), then `**Run:**`, then `**Device:**`; `[REVIEW_STATUS]` stays line 1 of `Review.md` and `[COVERS]` line 2 of `Walkthrough.md`
- files in the old layout (markers on top, `**Run:**` on line 2) still parse: every reader takes a marker at any position, and the readability lint skips the machine lines wherever they stand; a platform reviewer that writes the marker under the status line still works
- `docs/building-a-platform.md` states the closing block of `Review.md` and the `**Impact:**` field for platform reviewers; a platform reviewer from `spine-platform-swift` 1.31.0 and `spine-platform-kotlin` 1.20.0 follows both
- new templates in `task-documents`: `Done.md` (what the task changed, for the owner), `Plan.md` in two parts (`## For the owner`, `## For the implementer`), `Review.md` with an `**Impact:**` line on every finding, `Questions.md` with the question first (`**Question:**`, `**Decision:**`, `**Rejected:**`, `**Decided by:**`), `Research.md` opening with `## Short answer`, and `Validation.md` keeps the platform validator's structure under two rules: a plain-language Summary with no contract field names, and logs cited by their copy in the task folder
- the `Task.md` templates shrink to a pointer at the configuration document instead of repeating every setting
- `OpsChecklist.md` stays a list, one item per line; the lint reports a table as `format`
- Method B (the workflow skills) mirrors Method A (the profile scripts): the same lint run, the same fresh-reader check after Plan and after Done, the same one revision
