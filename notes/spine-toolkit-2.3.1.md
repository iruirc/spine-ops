- new script `scripts/lint-artifact-lang.sh` and convention `conventions/artifact-language.md`: the prose of a task's artifacts is measured against `[LANG]`. A part of 200 letters or more with under 10% in the project's script is a finding; a whole file is one only when none of its parts is. Code, tables, headings, fields, labels, paths, quotes and commit subjects are not prose, and in `OpsChecklist.md` only the text after an item's dash is. `en` and `ru` projects are both checked, each for the other's script
- the orchestrator runs it at the artifact budget's boundaries — including the step folders an epic ran and a review's new `Tasks/DONE/` path — and sends each file it names back once per run to the role that writes it, to rewrite that prose in the project language and nothing else. A finding still there afterwards is reported and the run carries on. New locale keys `lang_mismatch`, `lang_mismatch_persists`, `lang_readers_disagree` and `lang_mismatch_unowned`
- every brief now names the language in words and says it again as its last line, and names quoted logs and messages among what stays English; the walkthrough revision no longer takes its language from the reader's notes. A Method B subagent prompt does the same
- `ops-checklist` and `manual-checks` say which part of a line is structure and which is prose
- an artifact written in the wrong language before this release is caught by the first run of its task after it and costs one rewrite dispatch; closed tasks are never run, so never touched
- nothing the platforms vendor moved, so none of them has to re-vendor
