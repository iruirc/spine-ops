- the default estimate of a FEATURE and an EPIC is now a forecast of the agent run, not engineer days: `[ESTIMATION_UNIT]` = `agent-run` (the default), `days` or `both`. A project that wants the day estimate back writes `[ESTIMATION_UNIT] = [days]`; `## DeliveryMode` and `## AILeverage` are read only at `days` and `both`, so the template's `manual` line no longer chooses anything. BUG and REFACTOR keep their optional day estimate as before
- `[ESTIMATION]` = `auto`, `on` or `off` decides whether a task estimates at all: `auto` is `on` at `full` and `off` at `lite`, an explicit value stands, so a `lite` task can forecast and a `full` one can skip the section, its gate, the retrospective and the log row. The contract carries `estimation`, `estimation_unit` and `estimation_from`; an epic hands a step its own value with its own origin, and a `lite` plan that raises the scale estimates only when the value came from the scale
- new skill `run-forecast`: the Plan writes `## Estimation` → `### Run forecast` from the phase table — code phases, regression modules, a driver scenario, fix rounds — times coefficients that start `Low (uncalibrated)` and are overridden in `## AgentRunCoefficients`; the gates in manual count the Execute, Validation and Review runs. Done writes `## Estimate retrospective` in the same unit and one row per task in `Tasks/_calibration/agent-run-log.md`, a fixed 19-column table; an epic sums its steps' forecasts, a step's Plan refreshes its row, and the epic's rolled-up row is never calibrated on
- the readiness gate is shared by both units in `conventions/estimation-gate.md`: `Draft`, `Conditional` with a `pending_user` row, and a load-bearing unknown — one that would change the phase table — still stop Execute; the forecast's number never does
- `agent-metrics.sh`: each stage carries `spanMs`, its wall-clock span inside one run, summed across runs so the owner's wait between them is not counted; `--task` gives `runs`, `stageSpans`, `fixRounds`, `fixSpanMs`, `gateRuns` and `skippedSessions`; `--project-sessions` gathers a task's runs from every session of the project, and `--live-action fix-review` names the run still in flight. A fact with an unreadable session, or with no runs found, falls back to the git commit span, labelled `git` and kept out of calibration
- new script `run-calibration.sh <log>`: with three usable rows it prints, per coefficient, a row ready for `## AgentRunCoefficients` — the interquartile range in whole minutes, the median and the row count. Non-positive samples are dropped and named on stderr; nothing is written to the config without the owner
- in manual the orchestrator prints the FEATURE run forecast, its gates and its confidence before the prompt that follows Plan
- the FEATURE and EPIC briefs, the workflow skills, `task-documents`, `docs/configuration.md` and the template say the same; no file the platforms vendor changed
