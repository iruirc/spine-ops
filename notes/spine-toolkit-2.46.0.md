- `OpsChecklist.md` is gone, and the `ops-checklist` skill with it. New skill `ops-risks`: a closed list of seven operational risks a diff can show — `startup`, `lifecycle`, `stored-data`, `contract`, `rollout-flag`, `hot-path`, `release-settings` — each with its trigger in the diff, the proof it needs and who can give that proof. Security stays with `security-lens`
- at Plan (FEATURE, BUG, REFACTOR) the proof of each risk the task will trigger goes into the phase that gives it, and the risk into the plan's risks. At Review (FEATURE, BUG, REFACTOR, QUICK, REVIEW) a triggered risk with no proof is a finding: Major and blocking when code or a test can give it, Minor when it needs a measurement or the owner. `Review.md` carries `## Ops risks`, one line per triggered risk or `none triggered — the diff touches <X>`. Both scales apply it; there is no Pending, no `## Outstanding ops items` and no accept-or-defer, and a risk never becomes a case in `ManualChecks.md`. `release-settings` resolves topic **release ops** for what must agree
- Validation writes no checklist: the BUG and REFACTOR checklist modes, the Manual test pass item and `ops_checklist_path` in the validator's return are gone; a deferred check is still a case in `ManualChecks.md` and a title in `manual_checks`. `manual-checks` takes "the diff touches" from `ops-risks` → `## Touches`
- `feature-requirements` asks three more Secondary questions: Rollout switch, Stored data, Performance-sensitive path
- `lint-artifact-readability.sh` and `lint-artifact-lang.sh` no longer read `OpsChecklist.md`: the `format` class and the dash rule are gone. Files already in projects stay where they are and nothing reads them
- `long-run.sh start` refuses a `--log` inside a task folder (any folder with a `Task.md` above it), before writing anything; `conventions/agent-tooling.md` and every brief say logs live in `$TMPDIR`, and a log a document cites is copied alone into `phase-evidence/` or `validation-evidence/`
- new script `stage-leftovers.sh` finds what a stage left in the task folder: a shared allow-list (`.md`, `Run.json`, `_archive/`, `*.step/`, evidence folders without `long-run`'s side files), `snap` and `diff` after a stage with `--task-dir`, and `foreign` before the task's documents are committed, where the orchestrator asks to exclude, remove or commit the files it names. A nested repository is one finding, shown and never removed
- `core_compat` in `resolve-settings.sh`: the session's core against the `spine-toolkit` range of the installed platform. The orchestrator stops before the first stage when the core is outside that range (`error_core_older_than_platform`), and the opening block names a core that only lags the installed one
- a task id with no task stops with `error_task_not_found`, which now says how to create one, instead of creating a task
- Russian strings address the user in one form, the informal one; `conventions/i18n.md` records it and `lint-locales.sh` fails on the formal form
- the platforms' vendored `conventions/i18n.md` and `scripts/lint-locales.sh` changed; spine-platform-swift 1.40.0 and spine-platform-kotlin 1.28.0 carry them. A platform older than those still names `ops-checklist` and should be updated with this release
