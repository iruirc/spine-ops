- a generated package now carries the project's stack: `swift-tools-version` from the machine's toolchain, so it compiles in Swift 6 language mode; `platforms` from the new `defaults.platforms`; and a Swift Testing stub, or an XCTest one when `defaults.tests` says so
- `workspace.yml` gains `defaults.platforms` (a map of `ios` / `macos` to a version) and `defaults.tests` (`swift-testing` | `xctest`). `workspace-init` asks for both, `workspace-add --new` reads them, and a file without them keeps working: `ios 17.0`, `macos 14.0`, `swift-testing`
- `workspace-init` and `workspace-add --new` check `swift --version` at pre-flight and stop on a toolchain older than 6.0 instead of generating a Swift 5 package
- the two dependency arrays of a package's `Package.swift` are now marker-delimited and filled by `workspace-docs-regen` from `deps` and `external_deps` — `.package(path:)` beside `.package(url:)`, and `.product(name:package:)` in the target — so a declared dependency compiles. The tools version, `platforms`, `products` and every other target stay yours
- every run also names a manifest that has fallen behind the stack — an older tools version, a floor below `defaults.platforms`, an `external_deps` entry with no version requirement (SwiftPM has no such form, so it is left out) — and rewrites none of it. On a workspace created earlier that is two lines per package, on every run, until you raise them by hand
- **breaking:** `external_deps[].version` is now validated. It must be a map with exactly one of `from`, `exact`, `branch`, `revision`, or a bare semver string read as `from`, and `from` / `exact` values must be `M.m.p`. A hand-written `version: 1.0` or `version: { range: … }` used to reach only the docs; it now reaches `Package.swift`, where SwiftPM rejects it, so the validator rejects it first — which means `workspace-docs-regen` exits 2 until the file is fixed
- a workspace created before 1.15.0: run `/workspace-docs-regen --adopt`, review the diff and confirm. It puts the two arrays under markers when they are still the empty ones the template rendered; raising `swift-tools-version` and `platforms` of existing packages stays yours
