- new setting `[REPORT]` (`auto`, `on`, `off`; default `auto`) in `Task.md` and the project config, carried into a run as `report=auto|on|off` in the outbound contract: whether a task whose results spread over several artifacts leaves one topic document, the report, in a documentation component's `places`; numbers live whole only there, and `Done.md`, `Research.md` and `Plan.md` link to it
- `auto` resolves per profile: it stays `auto` (Plan decides) for TEST, FEATURE, RESEARCH and EPIC, becomes `off` for QUICK, BUG and REFACTOR unless the task says `on`, and is always `off` for REVIEW, where an `on` is turned into `off` with one stderr line instead of an error; an epic step inherits the epic's value and a step's own `Task.md` overrides it, both ways
- new skill `task-report` (with `agents/openai.yaml`, `allow_implicit_invocation: false`, and worked examples `examples/report.en.md` and `examples/report.ru.md`) holds every rule in seven sections: `## When` (three or more artifacts carry the results, more than one table of numbers, or the results decide something for later steps), `## Where` (a file named by its topic in the `places` of the state component whose `covers` the task touches; never the task folder), `## The decision`, `## The document` (eight required parts, one of them `Where sources disagree`), `## Updating` (new numbers next to old ones, labelled by the step's slug), `## Links`, `## Review`
- Plan writes two machine-readable fields under `## For the owner`: `[REPORT_DECISION] = needed | update | not-needed | unplaced` and `[REPORT_PATH] = <path from project root>`; a RESEARCH task writes them at the top of `Research.md`; `unplaced` asks a question in `Questions.md` instead of inventing a folder
- the implementing stage's role writes the report in a call of its own after the phases and before `Walkthrough.md`, marks the component's row in `Docs.md` `Applicable` with the file name, and commits it as `docs(<scope>): ...` in the repository that holds the file; Done then links the artifacts to it, and a `not-needed` whose criterion turned out to hold is rewritten to `needed` or `update` (no way back); a repeat Done with nothing to change answers `changed: false`, which is no failure
- Review reads the report against the artifacts: a number in `Done.md`, `Research.md` or `Plan.md` that the report lacks or contradicts is a blocking finding for `## For Done`; a missing decision field, an unnamed disagreement between sources and a `not-needed` that should have been `needed` are not blocking
- new `scripts/lint-report-links.sh <task-dir> [--root <project-root>]` checks, for a decision of `needed` or `update`, that the report file exists, that `Done.md`, `Plan.md` and `Research.md` each link to it (inline or reference link, URL-decoded, resolved against the artifact's own folder, so the link survives the move from `ACTIVE/` to `DONE/`), that the report names the task folder, and that it has a `Where sources disagree` heading or its Russian form; findings print as `report: <what>`; exit 0 nothing found or nothing to check, 1 findings, 2 usage, an unknown decision, `needed` with no path, or no project root; without `--root` the root is the folder of the project config
- `docs-route.sh audit` no longer names a document created under a component's `places` as "files created outside every covers — candidate for a new component": paths under any component's `places`, progress components included, now count as documentation, not as a subsystem being born
- all eight profiles carry the change in both Method A (the profile scripts: the byte-identical prelude gets the `REPORT` constants, `reportPlan()`, `reportReview()`, `writeReport(stage, extra)` and a clause in the Done brief) and Method B (the workflow skills); `scripts/lint-workflows.sh` and the foundation suite cover both
- no platform change: none of the six vendored files moved since 2.32.0 (`scripts/lint-manifest.sh`, `scripts/lint-i18n.sh`, `scripts/lint-locales.sh`, `scripts/lint-core-refs.sh`, `scripts/test-foundation.sh`, `conventions/i18n.md`), so no platform has to re-vendor
- source: a field task — its results spread over `Plan.md`, `Research.md`, `Done.md` and several documents under `Documents/`, and the summary `Documents/<topic>/Baseline.md`, written by hand, was reported by `docs-route.sh audit` as a candidate for a new component; with this release the same file is a report, and the audit does not name it
