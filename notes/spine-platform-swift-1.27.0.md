- **`workspace.yml` validation now enforces the archetype table**: every `deps` entry must point at an archetype the package's archetype may depend on (`engine` → `api-contract`; `library` and `feature` → `api-contract`, `engine`, `library`; `api-contract` → nothing). A workspace that already breaks it gets exit 2 from regen and `workspace-add`, with the edge and the fix named: `package 'X' (engine) may not depend on 'Y' (feature); list 'Y' in allowed_deps to allow it`
- `allowed_deps` now lists packages exempt from that table, default none; an entry that is not a package — such as an archetype name, which the old prompt invited — is its own error. The deps question asks right away, for each pick the table forbids, whether to record it as an exception or drop it, instead of failing after the whole dialog
- the Example/ question is gone from `workspace-init` and `workspace-add --new`, with Rule 13; `example_app` and `example_platform` in an existing `workspace.yml` are no longer read
- a workspace may declare apps and no packages; an empty `git.<remote>` URL is rejected, and the dialogs ask again on an empty answer
- the `workspace.yml` skeleton names every key the parser reads, including `project:`, `package_groups`, `group` and `allowed_deps`, and a test keeps its examples valid
- generated packages carry a `.gitignore` for `.build/`, `.swiftpm/`, `DerivedData/` and `.DS_Store`
- package rendering is `wspkg::render_to` and the `s06b` flags are `wsproj::swift_init_flags`; both skills call them, and so do the tests. `render_to` refuses a directory that already holds a `Package.swift`, so `workspace-add --incorporate` cannot overwrite the package it adopts; `workspace-init --resume` redoes a package render that was cut before `git init`
- `swift-init --di=plain` writes `manual` into `## Stack`, so setup no longer asks DI after the config exists and an interrupted answer can no longer leave `--resume` with nothing to redo
- `workspace-docs-regen --repair` never deletes a line: a duplicate pair loses its markers and keeps its text, and every restored `_END` and unwrapped pair is reported by file and marker; the linter's reason is printed instead of discarded
- regen writes the `.code-workspace` with jq and needs jq 1.7 or newer, so `1.50` and long integers in `settings` survive a change to `folders`; `--check` does not need jq, and a workspace with `code_workspace: false` does not either
